# bmo-cache-warmer

プロンプトキャッシュのための keepalive スケジューラーです。プロバイダーはプロンプトのプレフィックスを最後の使用からしばらく
キャッシュし、その後破棄します。すぐにまた使われるプレフィックスなら、作り直すより温めておくほうが安く済みます。ウォーマーは
登録されたプレフィックスの中身を知らないまま、それらを温かく保ちます。利用側は各ターゲットを、それが従うクロックとともに
登録し、使うたびに記録し、ターゲットへの ping フックを提供します。ウォーマーはパスを実行し、どのターゲットが期限を迎えたかを
判断して利用側に ping を依頼し、スイッチを管理し、すべての ping の記録を残します。他のサービスは呼び出しません。サービスに
加えて、クライアント、OpenAPI ドキュメント、ハーネスプラグイン(MCP サーバーとスキル)、そして依存関係を持たないクレート
としてのスケジュール規則を公開しています。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | サービスパッケージ:サービス、クライアント、OpenAPI ドキュメントと MCP サーバー、バイナリ |
| `schedule/` | スケジュールクレート:期限の規則と計画、および独自のテスト |
| `examples/` | リポジトリが保持する OpenAPI ドキュメントを出力するプログラム |
| `plugin/` | ハーネスプラグインのスキル |
| `policy/` | ウォーマー固有の固定値。バイナリに組み込まれる TOML ファイルです |
| `tests/` | リポジトリのチェックとサービスのテスト |
| `deploy/` | サービスの systemd ユーザーユニット。デプロイ時にデプロイツリーからリンクされます |
| `docs/` | サービスの動作についての正典となる文書と、OpenAPI ドキュメント |

ルートには、サービスパッケージのマニフェストを兼ねるワークスペースの Cargo マニフェスト、バージョン、韓国語台帳を伴う
`testbed.toml`、`install.toml`、`rustfmt.toml`、`CLAUDE.md`、そして `LICENSE` の MIT ライセンスが置かれています。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/api.md` | 境界:ワイヤ形式、ルート、イベント、ターゲット ping フック、コード、クライアント、スケジュールクレート、ハーネスプラグイン、バイナリのコマンド、デプロイされたサービス |
| `docs/openapi.json` | コードから書き出した OpenAPI 3.1 ドキュメントとしての契約 |
| `docs/warming.md` | パス、ターゲットが期限を迎える条件、グループ、各応答が残すもの、スイッチ、ポリシー |
| `docs/store.md` | ストアが保持するもの、その形の変わり方、スナップショットの取得・検査・復元の方法 |
| `docs/PERSONAL-DATA.md` | リポジトリのどのファイルにも含めてはならない個人情報、代わりに書くもの、そしてすべてのファイルを読んでそれを確かめるチェック |

## バージョン

- **リポジトリのバージョンは 1 つで、** ワークスペースのバージョンをすべてのメンバーパッケージが継承します。`VERSION` に
  記録され、各パッケージのバージョンはこれと一致します。
- **変更がバージョンをどう動かすか**は、`docs/api.md` の「Versioning」に記載されています。
